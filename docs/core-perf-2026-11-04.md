# KCP 核心优化与复测记录

> 版本说明：本文保留 v0.6.0 的实现与测量记录。v0.8.0 已将公开载荷改为 `Vec<u8>`，
> 单段接收继续转移已有分配；包解析改为借用切片并取得独立载荷，不再共享 `Bytes` 存储。
> 下述性能数字只对应当时版本，不作为 v0.8.0 的测量结论。

## 优化成果

v0.6.0 减少 KCP 热路径的复制、分配和重复扫描，保持公开 API 与协议行为不变：

- 合法 Push 输入只复制一次载荷，单段接收直接转移已有 `Bytes`。
- 默认 MTU 下每个实例省去一块未使用的 4284 B 缓冲，flush 不再构造两个临时批次数组。
- ACK 匹配与 RTT 采样合并，乱序插入复用标准库队列，不构造临时尾部数组。
- 0% 丢包相对原基线三轮复测耗时降低 8.31%–19.53%；20% 丢包隔离对照的两轮分别降低 18.26% 和 24.25%。

以下保留完整测量数据和方法，百分比对应特定工作负载，不扩展为公网吞吐或硬件缓存指标。

## 改动与静态依据

| 操作 | 修改前 | 修改后 |
| --- | --- | --- |
| `Kcp::input` 收到合法 Push | 复制整个报文、复制解析载荷、再复制入队载荷 | 借用切片解析，只有接收新段时复制载荷一次 |
| 控制包或丢弃的重复包 | 解析前分配并复制报文 | 不为解析分配报文缓冲 |
| 单段 `recv` | 新建缓冲并复制载荷 | 直接转移已有 `Bytes`，指针复用断言覆盖两种模式 |
| ACK 处理 | 验证与 RTT 采样分别扫描；快速重传扫描整个窗口 | 合并验证与采样，重复 ACK 提前退出，快速重传只处理相关前缀 |
| 乱序插入 | 多次查找，尾部弹出到临时 Vec 再放回 | 反向查找，标准库 `VecDeque::insert` 原地搬运较短一侧 |
| flush 数据批次 | 两个临时 Vec，保留整批载荷引用 | 死链预检后逐段输出，不分配批次数组 |
| `Kcp::new` 默认 MTU | 分配从不使用的 4284 B 缓冲及保留字段 | 删除私有死字段；不再分配该缓冲 |
| `KcpPacket::from_bytes` | 复制载荷 | 共享 `Bytes` 存储，保留原有输入推进和声明长度语义 |

表中复制、分配和扫描变化来自源码分析，不是硬件计数器测量；耗时结果见复测章节，
没有把总耗时收益归因于某个单独改动，也没有将其当作缓存命中率提升的证明。

保持报文格式、公开字段类型、ACK FIFO、una 推进、窗口、RTO、错误与取消处理语义。
删除无用途的 `Any` 字段后，`Kcp` 由编译器自动推导 Send/Sync，不再需要 unsafe 声明，
集成测试编译断言保证对应 trait 仍然成立。

## 不采用的优化与风险

- 没有同一 KCP 实例由多个线程同时写不同字段的证据，不添加缓存行 padding。
- 不自制 mask 环形队列，不占用公开 `fastack`、`xmit` 的高位，避免额外状态同步和兼容性风险。
- 不改拥塞控制或重传策略，不新增依赖，不改 Stream 架构。
- `KcpPacket` 的共享载荷可能延长较大原始分配的生命周期；文档明确此取舍。`Kcp::input(&[u8])` 仍按载荷长度取得独立所有权，不保留调用方 UDP 缓冲。
- 仿真计量不是实际网络吞吐、CPU 周期或缓存未命中率；跨平台表现、公网吞吐与硬件缓存指标未验证。
