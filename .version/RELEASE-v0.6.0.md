# v0.6.0

本版本优化 KCP 核心处理成本，减少报文复制、临时分配和重复扫描，
保持公开 API、feature、报文格式与重传策略不变。

## 主要变化

- 输入解析直接借用报文切片，仅为接受的新 Push 复制一次载荷；单段接收直接转移已有 `Bytes`，避免再次分配和复制。
- 公开数据包解析共享 `Bytes` 存储，`PacketBuilder` 接管传入的 Vec；默认 MTU 下每个 KCP 实例省去一块未使用的 4284 B 缓冲。
- 合并 ACK 查找与 RTT 采样，重复 ACK 提前退出，快速确认只扫描相关有序前缀；乱序接收使用标准库队列原地插入，取消临时尾部数组。
- flush 移除两个临时批次数组，保留整批死链预检和逐段输出成功后提交状态的规则，继续保证错误恢复与取消安全。
- 补齐载荷所有权、单段接收窗口恢复、ACK 去重、SN 回绕、队列复用和整批死链回归；移除不再需要的 unsafe Send/Sync 声明，由编译器推导并以测试保护。

## 性能结果

同机 Criterion 真实耗时对比中，0% 丢包、4 MiB 工作负载的三轮复测耗时降低
8.31%–19.53%；20% 丢包、12 KiB 工作负载在隔离新旧二进制的两轮对照中分别降低
18.26% 和 24.25%。

基准固定载荷与随机种子，逐消息校验内容并等待确认排空；结果包含连接创建、链路仿真、
校验及析构成本。完整轮次、其他丢包场景与测量方法见
[核心优化记录](https://github.com/cherish-ltt/kcp-ovo/blob/v0.6.0/docs/core-perf-2026-11-04.md)。

## 升级注意

- 将 Cargo 依赖要求从 `0.5.x` 更新为 `0.6.0`；现有 API 调用无需修改，Rust 最低版本仍为 1.99.1。
- `KcpPacket::from_bytes` 的载荷共享输入存储，可能延长原始分配的生命周期；`Kcp::input(&[u8])` 仍取得独立载荷所有权，调用后可立即复用 UDP 缓冲。
- 新基准组名为 `kcp_transfer_wall`，不再混入虚拟协议时长；勿与旧组 `kcp_transfer` 的结果比较，也不要用优化后结果覆盖优化前命名基线。
- 本地全量验证 344 项通过，另有 5 个既有文档用例 ignored；覆盖率工具报告总行覆盖率 95.53%、核心 97.20%，伴随 3 个函数数据不匹配提示，详细记录保留在优化文档中。
