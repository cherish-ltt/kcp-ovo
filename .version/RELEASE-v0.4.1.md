# v0.4.1

一个小版本，内容是一处时序缺陷修复，外加一轮黑盒与冒烟测试扩充：累计修复缺陷增至 28 个，
黑盒用例扩到 21 个套件，全量 285 个用例仍在 2 秒内跑完，行覆盖率 94.78%。

## 缺陷修复

**`Kcp::check()` 在零窗口时返回过晚的唤醒时刻**（中等级别）

零窗口期间 `snd_buf` 里往往仍有在途段在等 ACK，其重传期限远早于探测时刻
`ts_probe`（默认 5000ms）。原实现只要 `rmt_wnd == 0` 就直接返回 `ts_probe`，
把这个更早的期限盖掉了。按 `check()` 返回值调度的调用方会因此睡过重传期限，
重传粒度被放大到探测退避的量级——实测本应 20ms 唤醒的场景返回了 5000ms。

现在只有「没有在途段待重传」时才让探测时刻接管，否则返回最早的重传期限。

这**不是**严重级缺陷：不丢数据、不卡死、不 panic，只是唤起时机偏晚。
库自身不受影响——`KcpStream` / `KcpListener` 用固定 `update_interval` 驱动
`update()`，从不调用 `check()`；只有自行按 `check()` 调度 `update()` 的使用者才会遇到。

## 测试

| 指标 | 数值 |
| --- | --- |
| 黑盒套件 | 21 个 |
| 用例总数 | 285 |
| 行覆盖率 | 94.78% |
| 全量耗时 | 约 1.9 秒（虚拟时钟） |

新增套件 `smoke`：11 条秒级冒烟用例，覆盖五种预设配置各送一条消息、配置矩阵全互连、
空输入与退化配置拒绝、未知对端只放行一段探路、窗口通告解阻塞、控制帧往返、
双向同时传输、小消息边界、`mtu=29` 最小配置、同刻重复 `update` 不重发。
作为改动后的第一道快速反馈，全部跑完不到 10ms。

补充到既有套件的用例：

- `window`：`conv=0` 的会话绑定边界（绑定后换 `conv` 的重放包无法接管会话、
  首包为控制帧时同样触发绑定）；`peeksize` 与 `recv` 的长度一致性
  （流模式汇总全部可读段、消息模式等待分片链到齐）。
- `timing`：`check()` 在零窗口有在途段时返回重传期限的回归用例。
- `udp_smoke`：客户端被直接 drop 后 listener 仍能服务新客户端；
  关闭单个客户端不影响其余已建立连接。

## 升级注意

无需改动调用代码，行为变化仅限 `check()` 的返回值：

- 若你按 `check()` 返回值调度下一次 `update()`，零窗口期间会明显更早被唤醒，
  重传更及时。
- 若你按固定间隔轮询 `update()`，如 `KcpStream` 的做法，不会观察到任何变化。
