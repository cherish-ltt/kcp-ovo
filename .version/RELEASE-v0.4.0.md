# v0.4.0

本版本把协议核心按「黑盒测试挖缺陷 → 修复 → 补回归用例」的节奏过了一遍：
累计修复 27 个缺陷（其中 7 个会导致连接永久卡死、panic 或静默丢数据），
并把黑盒用例扩到 20 个套件 267 个用例，行覆盖率 94.46%。

## 亮点

- **新增 `fast_mode_with_wnd`**：在快速模式基础上显式指定收发窗口大小，
  不必再手写整份 `KcpConfig`。
- **新增吞吐基准**：`benches/` 迁到 criterion，提供 300ms 固定窗口吞吐基准，
  窗口放大至 512 段并重新标定数据量。
- **测试体系成型**：确定性虚拟链路（固定种子 + 虚拟时钟）覆盖丢包、乱序、重复、
  抖动、黑洞断网、成簇丢包、延迟尖刺、路径 MTU、SN 回绕与多连接并发。

## 缺陷修复

严重级（卡死 / panic / 静默丢数据）：

- 两端新建连接互相空等窗口探测，握手死锁。
- 重复 Push 段不回 ACK、首段（`sn=0`）永不被确认：ACK 丢失后双方永久不对账。
- SN 回绕时接收窗口判据失效，回绕点另一侧的合法段被丢弃。
- ACK 按 sn 精确删除与 una 推进并存，矛盾时会删除对端未收到的段。
- 越过 `snd_nxt` 的 una 被照单全收：一次比特翻转清空在途段，此后真实 ACK 全部
  被判过期，数据静默丢失。
- 发送额度不扣除在途段：每轮 flush 再塞满一个窗口，在途量无界增长。
- `mtu` 小于包头时下溢、等于包头时 `mss` 为 0 触发除零、零窗口配置永久不可用。

性能级（吞吐 / CPU 劣化）：

- 拥塞窗口三处失效：`ssthresh` 初值错误导致慢启动被整段跳过，`normal` 模式
  吞吐退化为 1 段/RTT；`fastresend == 0` 在干净链路上误判丢包。
- 重传段参与 RTT 采样，`rx_rttval` 偏大一个数量级，RTO 退避到十秒以上。
- 零窗口期间探测被同轮 ACK 挤掉，`check()` 持续返回 `current`，调用方全速空转。

其余为窗口通告、探测退避、`nodelay` 失效、`frg` 溢出、死链阈值等修正，
完整台账与回归用例索引见 `AGENTS.md` 第 10.3 节。

## 升级注意

- `Kcp::new` 现在会在构造期拒绝非法配置：`mtu` 不大于包头长度（28 字节）、
  `snd_wnd` 或 `rcv_wnd` 为 0 时返回 `KcpError::InvalidConfig`。
  此前这类配置会 panic 或让连接永久静默。
- 发送窗口语义修正后，在途段数严格受「发送窗口、对端通告窗口、拥塞窗口」三者
  最小值约束。窗口配置偏小的链路上，可见行为是发送速率被正确限制，而非此前的
  超发后被整片丢弃。
