# v0.5.0

本版本修复协议确认、重传、报文解析和 Stream 生命周期问题，并完善监听器资源限制及使用示例。

## 主要变化

- 拥塞窗口只在确认推进时增长；修正重传调度、RTT 方差和乱序 ACK 的快速重传，并为重复数据补发 ACK。
- 发送取消或输出失败时保留待处理状态；拒绝长度不符的报文和异常分片链，避免交付错误数据。
- Stream 在背压下继续处理协议，并在关闭时回收后台任务；超出消息分片上限的发送会立即返回错误。
- 监听器限制会话数量并回收空闲会话；客户端支持 IPv4 和 IPv6，零更新间隔会被拒绝。
- 文件传输示例先完整接收再提交文件，并使用应用层确认；更新 Echo 示例和使用文档。

## 升级注意

- `StreamConfig` 新增 `max_sessions` 和 `session_idle_timeout` 字段。完整结构体字面量需要补充字段，或使用 `..Default::default()`；默认最多 1024 个会话，300 秒未收到有效报文后回收。回收可能丢弃尚未交付的数据，客户端需要重新连接。
- `update_interval`、会话上限和空闲超时必须大于零。客户端使用解析出的第一个地址，不自动尝试后续地址。
- 高层 Stream 使用消息模式，单次发送最多 255 个分片；接收窗口不足以容纳完整消息时可能无法交付。发送成功只表示进入本地队列。
- 文件传输示例的应用协议需两端使用相同版本；接收端提交后的确认失败不代表文件未写入，目标文件替换行为取决于操作系统。
