# v0.5.2

本版本修复连续超时后的 normal/fast 退避及下一重传期限计算，保持公共 API、
feature 和协议线格式不变，无需修改现有调用。

## 主要变化

- 修复 #38：普通模式的段 RTO 增加 `max(rto, rx_rto)`，快速模式增加 `rto/2`（向下取整）；两者饱和累加并限制到 60 秒，下一超时期限使用更新后的 RTO。
- 普通模式仅在首次重传期限保留 `max(rx_rto/8, 1)` 毫秒余量；快速重传不增加段 RTO，重传 ACK 继续遵循 Karn 规则，不参与 RTT 采样。
- 增加五项回归，覆盖连续五次超时、u32/u64 时钟回绕、到期前不重传、上限与溢出、死链、ACK 恢复，以及 1 MiB 正常/成簇丢包/黑洞传输。
- 同步 README、公开配置文档、性能指南、缺陷台账及修复前后验证记录。

## 升级注意

- 退避修正会改变持续丢包下的恢复时刻、重传流量和达到死链阈值的时间；不能沿用 v0.5.1 的退避曲线调参。
- 不承诺 fast 在所有场景更快：固定种子仿真中，正常链路不变，部分 fast 成簇丢包/黑洞场景恢复更慢，十二格修复前后传输均逐字节完整交付。
- `nodelay` 不会令 `send` 或 `input` 自动输出，调用方仍需驱动 `update`；本次不修改下游 lynn_tcp 的调度或集成。
- 本地全量测试 336 passed，5 个既有文档用例 ignored；行覆盖率工具报告 95.47%，伴随 18 个函数数据不匹配警告，不能作为无警告覆盖率证明。

详细方法、数据及限制见 [v0.5.2 验证记录](https://github.com/cherish-ltt/kcp-ovo/blob/v0.5.2/docs/rto-backoff-v0.5.2.md)。
